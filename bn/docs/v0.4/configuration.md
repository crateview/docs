## কনফিগারেশন স্তর

অ্যাপ্লিকেশন ডিফল্ট `nuxt.config.ts` এবং `app/app.config.ts` এ সংজ্ঞায়িত করা হয়েছে। সার্ভার শুরু হলে এনভায়রনমেন্ট ভেরিয়েবল রানটাইম ডিফল্ট ওভাররাইড করে। ডেভেলপমেন্ট এবং বিল্ড কমান্ড `.env` পড়ুন; প্রোডাকশন নোড এন্ট্রিপয়েন্ট এটি স্বয়ংক্রিয়ভাবে পড়ে না।

রানটাইম এনভায়রনমেন্ট ভেরিয়েবল পরিবর্তন করার পর সার্ভার রিস্টার্ট করুন। উত্স-স্তরের উপাদান কনফিগারেশন সম্পাদনা করার জন্য একটি নতুন উত্পাদন বিল্ড প্রয়োজন৷

## রেজিস্ট্রি এবং সেশন সেটিংস

| পরিবর্তনশীল | ডিফল্ট | উদ্দেশ্য |
| ------------------------------ | ----------------------- | ----------------------------------- |
| `NUXT_REGISTRY_UPSTREAM` | `http://127.0.0.1:5000` | সার্ভার-সাইড রেজিস্ট্রি মূল। |
| `NUXT_REGISTRY_DELETE_ENABLED` | `false` | UI এ ম্যানিফেস্ট মুছে ফেলার প্রকাশ করুন। |
| `NUXT_SESSION_PASSWORD` | প্রক্রিয়া প্রতি র্যান্ডম | UI সেশন এনক্রিপ্ট করতে ব্যবহৃত গোপনীয়তা। |
| `HOST` | রানটাইম-নির্ভর | নোড সার্ভার শোনার ইন্টারফেস। |
| `PORT` | `3000` | নোড সার্ভার শোনার পোর্ট। |

আপস্ট্রিমটি অবশ্যই একটি HTTP(S) উত্স হতে হবে যা ফ্রন্টএন্ড সার্ভার থেকে পৌঁছানো যায়৷ শংসাপত্রগুলি URL এর বাইরে রাখুন। অনুরোধগুলি বর্তমান ব্যবহারকারীর প্রমাণীকরণ ব্যবহার করে; Crateview রেজিস্ট্রি অ্যাক্সেস নিয়ন্ত্রণ প্রতিস্থাপন করে না।

## পাবলিক ব্র্যান্ডিং ভেরিয়েবল

নীচের সমস্ত নাম `NUXT_PUBLIC_BRAND_` উপসর্গ ব্যবহার করে:

| প্রত্যয় | উদ্দেশ্য |
| ------------------------------------------- | ----------------------------------------------- |
| `NAME` | আবেদনের নাম। |
| `DESCRIPTION` | আবেদনের বিবরণ। |
| `LOGO_LIGHT`, `LOGO_DARK` | লোগো পাথ বা HTTP(S) ইউআরএল। |
| `FAVICON` | ব্রাউজার আইকন পাথ বা URL। |
| `TITLE_TEMPLATE` | পৃষ্ঠার শিরোনাম; `%s` পৃষ্ঠার শিরোনাম দ্বারা প্রতিস্থাপিত হয়েছে। |
| `PRODUCT_URL`, `DOCS_URL`, `REPOSITORY_URL` | ঐচ্ছিক নেভিগেশন লিঙ্ক. |

সর্বজনীন কনফিগারেশন ব্রাউজারে পাঠানো হয়। `NUXT_PUBLIC_*` ভেরিয়েবলে কখনই পাসওয়ার্ড বা টোকেন সংরক্ষণ করবেন না। রঙ এবং টাইপোগ্রাফি বিকল্পের জন্য [ব্র্যান্ডিং এবং থিমিং](/bn/docs/v0.4/theming) দেখুন।

## নেটওয়ার্ক বিন্যাস

ব্রাউজারটি Crateview এর সাথে একটি মূলে যোগাযোগ করে। Nitro রেজিস্ট্রি ক্লায়েন্টদের জন্য `/v2/**` প্রক্সি করে এবং `/api/registry/**` এর মাধ্যমে রেজিস্ট্রি মেটাডেটা পড়ে। এটি রেজিস্ট্রিতেই ক্রস-অরিজিন ব্রাউজার অ্যাক্সেসের প্রয়োজন এড়ায়।

একটি বিপরীত প্রক্সির পিছনে, পাবলিক অরিজিন এবং প্রোটোকল হেডার সংরক্ষণ করুন। পাবলিক ফ্রন্টএন্ড অ্যাড্রেস হল কপি করা pull কমান্ডে প্রদর্শিত রেজিস্ট্রি ঠিকানা। দূরবর্তী প্রমাণীকৃত ব্যবহারের জন্য, ব্রাউজার বা CLI শংসাপত্র গ্রহণ করার আগে সঠিকভাবে HTTPS সমাপ্ত করুন।

## Compose বনাম স্বতন্ত্র কনফিগারেশন

বান্ডেল করা Compose ফাইলটি ইচ্ছাকৃতভাবে `NUXT_REGISTRY_UPSTREAM=http://registry:5000` এর সাথে তার নিজস্ব `registry` পরিষেবার সাথে সংযোগ করে৷ একটি কন্টেইনার স্থাপনায় অন্য রেজিস্ট্রি ব্যবহার করতে, সেই পরিষেবা পরিবেশকে মানিয়ে নিন বা আলাদাভাবে ফ্রন্টএন্ড চালান। অনুমান করবেন না একটি হোস্ট-লুপব্যাক রেজিস্ট্রি একটি কন্টেইনার গেটওয়ের মাধ্যমে পৌঁছানো যায়৷
## এই সংস্করণের কনফিগারেশন

পর্যবেক্ষণ ঐচ্ছিক, সাধারণত বন্ধ। চালু থাকলে সারসংক্ষেপ ড্যাশবোর্ড; নইলে /home থেকে /explore যায়। চালু করলে পাবলিক রেজিস্ট্রির বেনামি দর্শকসহ সব UI ব্যবহারকারী পুরো রেজিস্ট্রির পরিচালন তথ্য পায়। পরিচালিত টোকেন মোডে বৈশ্বিক পড়ার অনুমতিও লাগে।.

| ENV | Default |
| --- | --- |
| `NUXT_MONITORING_ENABLED` | `false` |
| `NUXT_MONITORING_METRICS_URL` | — |
| `NUXT_MONITORING_METRICS_TOKEN` | — |
| `NUXT_MONITORING_WEBHOOK_SECRET` | — |
| `NUXT_MONITORING_DATABASE_PATH` | `.dev/monitoring.sqlite` |
