## ম্যানিফেস্ট মোছা সক্ষম করুন

ডিফল্টরূপে Crateview UI-তে মুছে ফেলা অক্ষম করা আছে। ফ্রন্টএন্ড এবং Distribution উভয়কেই এটির অনুমতি দিতে হবে:

```dotenv
NUXT_REGISTRY_DELETE_ENABLED=true
```

```yaml
storage:
  delete:
    enabled: true
```

Distribution এছাড়াও `REGISTRY_STORAGE_DELETE_ENABLED=true` পড়তে পারেন। তাদের পরিবেশ বা কনফিগারেশন পরিবর্তন করার পরে প্রাসঙ্গিক পরিষেবাগুলি পুনরায় চালু করুন। `/v2/**` এর মাধ্যমে সরাসরি করা অনুরোধ সহ অনুমোদনের জন্য রেজিস্ট্রি দায়ী থাকে।

## digest মুছে ফেলা বুঝুন

স্ট্যান্ডার্ড ডিলিট অপারেশন একটি **মেনিফেস্ট digest**কে লক্ষ্য করে। digest নির্দেশ করে প্রতিটি ট্যাগ সরানো যেতে পারে। Crateview নিশ্চিতকরণের আগে প্রভাবিত ট্যাগগুলির পূর্বরূপ দেখায়, কিন্তু একজন সমবর্তী লেখক পূর্বরূপের পরে রেফারেন্স পরিবর্তন করতে পারেন: রেজিস্ট্রি API উপনাম লক করে এমন একটি লেনদেন প্রদান করে না।

একটি মুছে ফেলাকে ম্যানিফেস্ট এবং এর সমস্ত উপনামের পরিবর্তন হিসাবে বিবেচনা করুন, একটি লেবেল অপসারণ হিসাবে নয়। নিশ্চিত করার আগে আপনার ব্যাকআপ এবং উদ্দিষ্ট সুযোগ যাচাই করুন।


টেবিল থেকে এক বা একাধিক ট্যাগ বেছে মুছে ফেলা নিশ্চিত করুন। প্রাকদর্শন আক্রান্ত ট্যাগ হালনাগাদ করে, প্রতিটি digest একবার মুছে এবং আংশিক ব্যর্থতা জানায়। সব উপনাম আক্রান্ত। গার্বেজ সংগ্রহ আলাদা রেজিস্ট্রি কাজ।

## আবর্জনা সংগ্রহ এবং ব্যাকআপ

একটি ম্যানিফেস্ট মুছে ফেলা অবিলম্বে ডিস্ক পুনরুদ্ধারের প্রতিশ্রুতি দেয় না৷ আবর্জনা সংগ্রহ একটি পৃথক রেজিস্ট্রি প্রশাসনের কাজ; Crateview এটি চালায় না।

স্টোরেজ ড্রাইভারের জন্য উপযুক্ত পদ্ধতি ব্যবহার করে আপনার রেজিস্ট্রি স্টোরেজ এবং এর কনফিগারেশন ব্যাক আপ করুন। পাত্রে প্রতিস্থাপন করার সময় ভলিউম রাখুন। আবর্জনা সংগ্রহের জন্য Distribution-এর নির্দেশাবলী অনুসরণ করুন এবং সমন্বয় লিখুন:

- [Distribution আবর্জনা সংগ্রহ](https://distribution.github.io/distribution/about/garbage-collection/)
- [Distribution কনফিগারেশন](https://distribution.github.io/distribution/about/configuration/)

## Crateview আপডেট করুন

রিলিজ নোটগুলি পর্যালোচনা করুন, `CRATEVIEW_VERSION` পছন্দসই `v`-প্রিফিক্সড রিলিজ ট্যাগে `.env` সেট করুন এবং ফ্রন্টএন্ড কন্টেইনারটি প্রতিস্থাপন করুন:

```sh
docker compose pull frontend
docker compose up -d --no-deps frontend
```

উদাহরণস্বরূপ, প্রাথমিক রিলিজ `CRATEVIEW_VERSION=v0.7.0` ব্যবহার করে। রোল ব্যাক করতে, পূর্ববর্তী ট্যাগটি পুনরুদ্ধার করুন এবং এই কমান্ডগুলি পুনরাবৃত্তি করুন। রানটাইম পরিবেশ এবং `registry-data` ভলিউম রাখুন; `docker compose down --volumes` চালাবেন না। উত্স বিল্ডগুলি `compose.build.yaml` এর মাধ্যমে উপলব্ধ থাকে৷

নির্ভরতা আপডেট প্রস্তাব করার জন্য উৎস সংগ্রহস্থলে Dependabot কনফিগার করা হয়েছে; এটি স্বয়ংক্রিয়ভাবে আপনার স্ব-হোস্টেড স্থাপনা আপগ্রেড করে না। আপগ্রেড করার পরে রেজিস্ট্রি সংযোগ, সাইন-ইন এবং প্রভাবিত ক্রিয়াগুলি পুনরায় পরীক্ষা করুন।

## বড় রেজিস্ট্রি

সংগ্রহস্থল অনুসন্ধান সম্পূর্ণ পাতাযুক্ত ক্যাটালগ পড়ে। দৃশ্যমান সংগ্রহস্থলের জন্য মেটাডেটা চাহিদা অনুযায়ী আনা হয়। ছবি তৈরির সময় অনুসারে একটি বড় ট্যাগ তালিকা বাছাই করার জন্য অনেকগুলি ম্যানিফেস্ট এবং কনফিগারেশন পড়ার প্রয়োজন হতে পারে। Crateview এর কোনো ব্যাকগ্রাউন্ড মেটাডেটা সূচক বা বাহ্যিক অনুসন্ধান পরিষেবা নেই।
