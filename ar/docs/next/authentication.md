## المصادقة المدعومة

يدعم Crateview السجلات المجهولة، وhtpasswd Basic Auth الأصلي وخدمة Crateview auth الاختيارية في وضع الرمز المميز. يقوم بالتحقق من `/v2/` ويعرض نموذج تسجيل الدخول عندما يتطلب التسجيل المصادقة الأساسية.

لم يتم دمج خدمات الرمز المميز Bearer الخارجية وOIDC. تنتج خدمات الرمز المميز الخارجية غير المكونة إشعارًا صريحًا غير مدعوم auth.

## جانب التسجيل Basic Auth

قم بإنشاء ملف htpasswd باستخدام كلمة مرور bcrypt. يستخدم المثال التالي حاوية Apache رسمية مؤقتة؛ استبدل بيانات اعتماد المثال وقم بحماية الملف الناتج:

```sh
mkdir -p auth
docker run --rm --entrypoint htpasswd httpd:2   -Bbn your-user choose-a-strong-password > auth/htpasswd
```

مثال على إعدادات Distribution:

```yaml
auth:
  htpasswd:
    realm: Registry
    path: /auth/htpasswd
```

قم بتحميل الملف الذي تم إنشاؤه في حاوية التسجيل على `/auth/htpasswd`. تكوين التسجيل منفصل عن تكوين Crateview. استخدم HTTPS للوصول عن بعد؛ Basic Auth هو تشفير وليس تشفير نقل. تجنب ترك كلمات مرور حقيقية في سجل الصدفة المشترك أو الأمثلة العامة.

## جلسات واجهة المستخدم

يقوم خادم Nitro بالتحقق من صحة بيانات الاعتماد مقابل السجل. يقوم بتخزينها في ملف تعريف ارتباط مشفر HttpOnly SameSite=Strict. لا يتلقى متصفح JavaScript وlocalStorage بيانات الاعتماد. تنتهي الجلسات بعد ثماني ساعات.

قم بتعيين سر جلسة إنتاج عشوائية:

```sh
openssl rand -base64 32
```

استخدم القيمة التي تم إنشاؤها كـ `NUXT_SESSION_PASSWORD`، مع 32 حرفًا على الأقل. يجب أن يستخدم كل مثيل للواجهة الأمامية خلف موازن التحميل نفس القيمة. بدون التكوين، يقوم Crateview بإنشاء سر العملية المحلية، وبالتالي فإن إعادة التشغيل تؤدي إلى إبطال الجلسات الحالية.

## HTTPS وتسجيل الخروج

يستخدم ملف تعريف ارتباط الجلسة Secure عندما يكون بروتوكول الطلب العام هو HTTPS. قم بتكوين بروتوكول إعادة توجيه الوكيل العكسي بشكل صحيح. يؤدي تسجيل الخروج إلى مسح جلسة واجهة المستخدم؛ ولا يحذف أو يعدل مستخدمي التسجيل.

يقوم Docker وعملاء CLI الآخرين بالمصادقة مباشرة من خلال وكيل `/v2/**` باستخدام بيانات اعتماد التسجيل العادية الخاصة بهم. لا يؤدي تسجيل الدخول إلى واجهة مستخدم الويب إلى تسجيل دخول Docker CLI تلقائيًا.

## إدارة الحساب الاختيارية

تدعم خدمة إدارة/auth المستقلة إنشاء الحساب وتغيير كلمة المرور الخاصة. يتصل Docker مباشرة بالسجل ويعمل بدون حاوية واجهة المستخدم. يبقى المستخدمون وتجزئة bcrypt في `htpasswd`؛ أذونات الرمز المميز موجودة في `permissions.json`. تخزين الحساب لا يستخدم SQLite.

- **الوضع الأساسي:** يتحقق Distribution من ملف htpasswd المشترك؛ جميع المستخدمين لديهم حق الوصول إلى التسجيل على قدم المساواة. لا يتطلب Docker تشغيل خدمة الإدارة.
- **وضع الرمز المميز:** تصدر خدمة auth المستقلة رموزًا موقعة مدتها خمس دقائق؛ يفرض Distribution أذونات المستودع. يتطلب Docker التسجيل وخدمة auth. ليس لدى المستخدمين الجدد في البداية حق الوصول إلى المستودع.
- **UI:** تتحكم قائمة السماح على الخادم في عرض الحسابات وإنشائها وإعادة تعيين كلمات المرور وحذفها. `NUXT_USER_CREATION_ALLOWED_USERS`: `alice,bob`; `*`. تمنع القيمة الفارغة الإدارة؛ وتُسمح الأسماء المدرجة، ويسمح الرمز البديل لكل مستخدم مصادق عليه.
- **الأذونات:** تمنح واجهة سطر الأوامر (CLI) المستودعات المستهدفة أو مساحات الأسماء (`team/*`) أو كل شيء (`*`)؛ الملفات الشخصية هي `reader` (pull)، و`writer` (pull/push)، و`manager` (pull/push/حذف). لا يحتوي الوضع الأساسي على أدوار التسجيل.

قم بتمكين `NUXT_AUTH_MODE=htpasswd` أو `token` بشكل صريح وقم بتكوين `NUXT_AUTH_SERVICE_URL` الداخلي و`NUXT_AUTH_SERVICE_SECRET` للخادم فقط. يتطلب وضع الرمز المميز أيضًا أن يتطابق `NUXT_AUTH_TOKEN_REALM` مع نقطة نهاية الرمز المميز العام تمامًا. لا تدعم السجلات المجهولة وخدمات الرموز الخارجية إدارة الحسابات المحلية. تُدار صلاحيات المستودعات عبر واجهة سطر أوامر المصادقة؛ وتعرضها الواجهة للقراءة فقط.

راجع [دليل خدمة الحساب ](https://github.com/crateview/registry-ui/blob/3844d7605dac80d0d58999201c43e94c644d72c0/auth/README.md) للتعرف على تراكبات Compose والإعداد والترحيل وأوامر CLI. قم بتوجيه الوصول العام إلى Docker مباشرة إلى السجل بشكل مستقل عن واجهة المستخدم. تظل الرموز المميزة التي تم إصدارها مسبقًا صالحة لمدة تصل إلى خمس دقائق بعد تغيير كلمة المرور أو إلغاء الإذن.

تجمع الإدارة الإعدادات والمستخدمين. توفر قائمة الحساب اللغة والمظهر أيضاً. يغيّر الحساب كلمة مرورك بعد التحقق من الحالية. تتحكم قائمة سماح الخادم في عرض الحسابات وإنشائها؛ صلاحيات الرموز للقراءة فقط. كلمات المرور الجديدة12 محرفاً على الأقل و72 بايت UTF-8 كحد أقصى. لا تملك حسابات الرموز الجديدة وصولاً أولياً للمستودعات.

تتحكم قائمة السماح على الخادم في عرض الحسابات وإنشائها وإعادة تعيين كلمات المرور وحذفها. تتيح قائمة النقاط الثلاث المحاذاة إلى اليمين للمسؤولين إعادة تعيين كلمة مرور مستخدم آخر دون كلمة المرور القديمة أو حذف حسابه بعد التأكيد. تحتفظ إعادة التعيين بصلاحيات المستودعات؛ ويحذف حذف الحساب تلك الصلاحيات. تفتح قائمتك الخاصة صفحة الحساب لتغيير كلمة المرور باستخدام الحالية؛ ولا يمكن حذف حسابك الخاص.
