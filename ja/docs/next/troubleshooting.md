## UI がレジストリにアクセスできません

フロントエンドサーバーのネットワーク環境からレジストリの起点を確認してください。コンテナーでは、`localhost` はコンテナー自体を指します。一般的な Compose アップストリームは `http://registry:5000` です。

```sh
curl -i http://127.0.0.1:5000/v2/
```

匿名レジストリは成功を返すはずです。認証されたものは、`WWW-Authenticate` チャレンジとともに `401` を返すことができます。接続の拒否は、リスナー、アドレス、またはネットワーク パスの準備ができていないことを意味します。

## サインインが失敗する

Crateview は、匿名レジストリ、ネイティブ htpasswd Basic Auth、およびトークン モードのオプションの Crateview auth サービスをサポートします。 `/v2/` を調査し、レジストリで基本認証が必要な場合にサインイン フォームを表示します。

外部の Bearer トークン サービスと OIDC は統合されていません。未構成の外部トークン サービスでは、明示的な unsupported-auth 通知が生成されます。

セッション損失が繰り返される場合は、すべてのフロントエンド インスタンスが `NUXT_SESSION_PASSWORD` を共有していることを確認してください。プロセスローカルで生成されたシークレットは、再起動後に変更されます。また、HTTPS と転送されたプロトコル ヘッダーも確認します。ブラウザセッションでは、Cookie が同じオリジンに戻る必要があります。

## 私の画像には説明も作成日もありません

これらの値はマニフェストの注釈またはイメージ構成に存在する必要があります。 Crateview は、欠落しているメタデータを推論したり、レジストリ push 回を置き換えたりしません。イメージを構築するときに、適切な OCI 注釈を追加します。

## リファラーが空です

レジストリは、OCI リファラー エンドポイントまたは標準の digest タグ フォールバック インデックスを公開する必要があります。 OCI クライアントは、必要に応じてそのフォールバック インデックスを維持する責任があります。リファラーのサポートなしで、サブジェクトを含むマニフェストをレジストリにプッシュするだけでは、Crateview はそのマニフェストのすべてのタグをスキャンしません。

## 削除が見つからないか、拒否されました

Crateview の `NUXT_REGISTRY_DELETE_ENABLED` と Distribution の両方のストレージ削除設定を有効にします。レジストリは、そのアクセス許可または実装に応じてリクエストを拒否することができます。削除は digest によって機能し、複数のタグに影響を与える可能性があります。

## 本番環境では .env ファイルが無視されます

`node .output/server/index.mjs` は `.env` を自動的にロードしません。プロセス マネージャー、コンテナー環境、またはシェルを通じて変数をエクスポートします。ランタイム値を変更した後、再起動します。静的専用 Web ホストは、必要な Nitro サーバーを置き換えることはできません。

## コピーした pull コマンドが機能しない

このコマンドはパブリック フロントエンド アドレスを使用します。 CLI がそのオリジンに到達でき、その TLS 証明書を信頼できることを確認します。必要に応じて CLI を個別に認証します。ブラウザーのサインインでは、Docker CLI ログインは作成されません。

再現可能な UI の問題が見つかった場合は、影響を受けるリビジョンとサニタイズされた再現の詳細を含む [issue](https://github.com/crateview/registry-ui/issues)] を開きます。脆弱性については [プライベート セキュリティ チャネル ](https://github.com/crateview/registry-ui/security/policy) を使用してください。
## 監視

この版の設定: [監視](/ja/docs/next/monitoring).

この版の設定 — 監視は任意で初期状態は無効です。有効時は概要がダッシュボードを開き、無効時は /home が /explore に転送されます。有効化すると公開レジストリの匿名訪問者を含む全UI利用者にレジストリ全体の運用情報が公開されます。管理トークンモードでは全体の読み取り権限も必要です。

## PWA のインストールまたはオフライン起動ができない

ブラウザーの対応状況、HTTPS または localhost、本番ビルドを確認してください。まずオンラインでアクセスし Worker をインストールします。`manifest.webmanifest` と `sw.js` は設定済みの `NUXT_APP_BASE_URL` 配下で Crateview に届く必要があります。リバースプロキシはプレフィックスを保持し、正しいマニフェストと JavaScript を返してください。

ネットワークがない場合のオフライン表示は正常で、保存済みのリポジトリやアカウントのデータは提供しません。再接続して再試行してください。アイコンが違う場合は PNG サイズ、コンテナパスの権限、ファイル優先設定、起動エラーを確認し、変更後に再起動してください。ブラウザーが後からアイコンを更新する場合があります。
