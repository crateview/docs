## 構成レイヤー

アプリケーションのデフォルトは、`nuxt.config.ts` および `app/app.config.ts` で定義されます。環境変数は、サーバーの起動時に実行時のデフォルトをオーバーライドします。開発およびビルド コマンドは `.env` を読み取ります。運用ノードのエントリポイントは、それを自動的に読み取りません。

ランタイム環境変数を変更した後、サーバーを再起動します。ソースレベルのコンポーネント構成を編集するには、新しい実稼働ビルドが必要です。

## レジストリとセッションの設定

| 変数 | デフォルト | 目的 |
| ------------------------------ | ----------------------- | ----------------------------------- |
| `NUXT_REGISTRY_UPSTREAM` | `http://127.0.0.1:5000` | サーバー側レジストリの起点。 |
| `NUXT_REGISTRY_DELETE_ENABLED` | `false` | UI でマニフェストの削除を公開します。 |
| `NUXT_SESSION_PASSWORD` | プロセスごとにランダム | UI セッションの暗号化に使用されるシークレット。 |
| `HOST` | ランタイムに依存する | ノードサーバーのリスニングインターフェイス。 |
| `PORT` | `3000` | ノードサーバーのリスニングポート。 |

アップストリームは、フロントエンド サーバーから到達可能な HTTP(S) オリジンである必要があります。 URL に資格情報を含めないでください。リクエストでは現在のユーザーの認証が使用されます。 Crateview は、レジストリ アクセス制御を置き換えるものではありません。

## パブリックブランディング変数

以下のすべての名前では、接頭辞 `NUXT_PUBLIC_BRAND_` が使用されます。

| サフィックス | 目的 |
| ------------------------------------------- | ----------------------------------------------- |
| `NAME` | アプリケーション名。 |
| `DESCRIPTION` | アプリケーションの説明。 |
| `LOGO_LIGHT`、`LOGO_DARK` | ロゴ パスまたは HTTP(S) URL。 |
| `FAVICON` | ブラウザアイコンのパスまたはURL。 |
| `TITLE_TEMPLATE` | ページタイトル; `%s` はページのタイトルに置き換えられます。 |
| `PRODUCT_URL`、`DOCS_URL`、`REPOSITORY_URL` | オプションのナビゲーション リンク。 |

パブリック設定はブラウザに送信されます。パスワードやトークンを `NUXT_PUBLIC_*` 変数に保存しないでください。色とタイポグラフィのオプションについては、[ブランディングとテーマ](/ja/docs/next/theming)]を参照してください。

## ネットワークレイアウト

ブラウザは 1 つのオリジンで Crateview と通信します。 Nitro は、レジストリ クライアントに対して `/v2/**` をプロキシし、`/api/registry/**` を通じてレジストリ メタデータを読み取ります。これにより、レジストリ自体へのクロスオリジン ブラウザー アクセスが必要なくなります。

リバース プロキシの背後で、パブリック オリジン ヘッダーとプロトコル ヘッダーを保持します。パブリック フロントエンド アドレスは、コピーされた pull コマンドに表示されるレジストリ アドレスでもあります。リモート認証使用の場合は、ブラウザまたは CLI 認証情報を受け入れる前に HTTPS を正しく終了してください。

## Compose 構成とスタンドアロン構成の比較

バンドルされている Compose ファイルは、意図的に `NUXT_REGISTRY_UPSTREAM=http://registry:5000` を使用して独自の `registry` サービスに接続します。コンテナーのデプロイメントで別のレジストリーを使用するには、そのサービス環境を適応させるか、フロントエンドを個別に実行します。コンテナー ゲートウェイを介してホスト ループバック レジストリに到達できると想定しないでください。

管理には設定とユーザーがあります。アカウントメニューでも言語とテーマを選べます。アカウントでは現在のパスワードを確認して自分のパスワードを変更します。ユーザー一覧と作成はサーバー許可リストで制御され、トークン権限は読み取り専用です。新しいパスワードは12文字以上72 UTF-8バイト以下です。新しいトークンアカウントには最初リポジトリ権限がありません。

サーバーの許可リストがアカウントの一覧表示、作成、パスワードリセット、削除を制御します。 右端の三点メニューから、管理者は他のユーザーのパスワードを古いパスワードなしでリセットしたり、確認後にアカウントを削除したりできます。リセットではリポジトリ権限を保持し、削除では権限も削除します。自分のメニューは「アカウント」を開き、現在のパスワードで変更を確認します。自分のアカウントは削除できません。

## PWA アイコンの設定

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `NUXT_PUBLIC_BRAND_PWA_ICON_192` | `/branding/pwa-192.png` | 192 ピクセルのインストールアイコン URL。 |
| `NUXT_PUBLIC_BRAND_PWA_ICON_512` | `/branding/pwa-512.png` | 512 ピクセルのインストールアイコン URL。 |
| `NUXT_BRAND_PWA_ICON_192_FILE` | — | 優先する非公開 192 ピクセル PNG ファイル。 |
| `NUXT_BRAND_PWA_ICON_512_FILE` | — | 優先する非公開 512 ピクセル PNG ファイル。 |

ローカルファイルは対応する公開 URL より優先されます。読み取り可能で空でない、指定どおりの正方形サイズの PNG が必要です。不正なファイルはサーバー起動を停止します。相対パスはサーバーの作業ディレクトリ基準です。コンテナパスは内部の読み取り可能なファイルを指す必要があります。変更後は再起動してください。

ローカルアイコン URL とマニフェストは `NUXT_APP_BASE_URL`（例：`/registry/`）に従い、外部 HTTP(S) URL は保持されます。非公開ファイル変数を秘密情報の保存に使わないでください。画像内容は公開され、ファイルシステムのパスだけがサーバー側に残ります。
